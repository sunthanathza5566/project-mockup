## Sidebar ต่อ role
- อาจารย์/เจ้าหน้าที่: งานของฉัน (1) · จัดทำ SAR (3) · ข้อมูลหลักสูตร (3) · อ้างอิง (1) = 8 รายการ ใช้จริงบ่อยแค่ 3 แต่มีหัวกลุ่มเลยสแกนได้ — ผ่าน · คำว่า "จัดทำ SAR" ควรมีคำไทยกำกับสำหรับคนใหม่ (m7)
- chair: ได้ "รอตรวจ" อยู่กลุ่มบนสุด — เหมาะ
- fqa/dean: ได้ "รอตรวจ" แต่งานจริงอยู่ที่แดชบอร์ดรอบ (cycle-tasks ช่วยพาไป) — ผ่าน
- กรรมการ: home, รอบประเมิน, หลักฐาน, ส่งออก, คลังเกณฑ์ — งานหลัก (พื้นที่ทำงานกรรมการ) ไม่มีในเมนู ต้องผ่าน todo หรือ รอบ → รอบ → ปุ่ม (3 คลิก) · ยอมรับได้เพราะ todo พาไป 1 คลิก
- ผู้ดูแล: ครบ
- ปุ่ม "การแสดงผล" (ขนาดตัวอักษร) อยู่ล่างสุดของ sidebar/ใน drawer — ผู้ใช้ 50+ ที่ต้องการที่สุดจะหาไม่เจอ (m3)

## หน้าหลัก "สิ่งที่ต้องทำตอนนี้" — ตรวจ 13 ชนิด todo
ครบตามงานเขียน/ตรวจ/อนุมัติ/ประเมิน/PII/แผนปรับปรุง แต่ **ขาด 2 ขั้นของ lifecycle รอบ** และมีข้อกำกวม:
1. ไม่มี todo `close_cycle` สำหรับผู้มี `cycle.close` เมื่อรอบ `assessed` — B3 ส่ง noti ให้แล้วแต่หน้าหลักขึ้น "ไม่มีงานค้าง" (ขัดกันเอง)
2. ไม่มี todo สำหรับ chair ให้เปลี่ยนรอบ `draft → in_progress` (ถ้าเป็นขั้นที่ต้องกดเอง — U0 lect1 ต้องรอ chair ทำในรอบ draft) · ถ้าไม่ต้องกด ให้ ADR เขียนชัดว่าไม่ต้องมี
3. `assess_cycle` เมื่อให้คะแนนครบ 8/8 แต่ยังไม่เลือก verdict หรือยังไม่กดส่ง — titleTh ยังเป็น "(ให้คะแนนแล้ว 8/8)" ดูเหมือนเสร็จแล้ว ควรเปลี่ยนข้อความเป็น "ส่งผลประเมินรอบ {ปี}" เมื่อ k=8
4. ผู้ใช้หลายบทบาท (เช่น uadmin, chair ที่เป็นอาจารย์ด้วย) ไม่ได้ระบุว่า empty state ใช้ข้อความของบทบาทไหน
5. งานเดียวกันขึ้นทั้ง todo และแจ้งเตือนในหน้าเดียว (เช่น 3.6 ถูกส่งกลับ) — ยอมรับได้ แต่ควรบอกว่า "ทำเครื่องหมายว่าอ่านแล้ว" ไม่ลบ todo

## ลูกเล่นที่อาจรำคาญผู้ใช้ 50+
ตรวจทั้ง L1–L14 + ข้อห้าม 12 ข้อ: **ไม่พบตัวที่น่ารำคาญ** — ไม่มีอะไรวนบนหน้าที่ต้องอ่าน, ฉลองครั้งเดียวและปิดได้, toast มีเส้นเวลาและหยุดเมื่อ hover, skeleton รอ 300ms ก่อนขึ้น · ข้อเดียวที่ควรระวัง: card hover ยก -2px บนการ์ด todo/heatmap 53 ช่อง ทำให้ heatmap "ขยับ" ตามเมาส์ตลอดเวลาที่ลากผ่าน → แนะนำให้ heat cell ใช้แค่เปลี่ยนขอบ/เงา ไม่เลื่อน (ADR ข้อ 4 L1)

## สิ่งที่ spec ทำได้ดี (ใช้เป็นผลได้)
- หน้าหลักต่อ role + empty state ที่บอกว่าต้องรออะไร/ทำอะไรได้ระหว่างรอ (ตอบ AC-15 ได้ทุก role ยกเว้น M1)
- preflight ของคณบดีแสดงทั้งก่อนกดและใน dialog + ปุ่ม danger แยกห่าง (ตอบ AC-16)
- ฟอร์มหลักฐาน: ปุ่มเพิ่มอยู่ใน header, 3 ช่องหลัก, inline error + error summary, query `?new=1&req=` จากหน้าข้อ, ไฮไลต์+scroll แถวใหม่ → AC-14 คาดว่าผ่าน
- ตัดสินไม่ทำ "อนุมัติเป็นชุด" พร้อมเหตุผลด้าน QA/segregation — ถูกต้อง
- ข้อห้าม gamification ผูกงานจริงเท่านั้น (ไม่มี leaderboard/แต้ม/streak) และห้ามฉลองผล AI
