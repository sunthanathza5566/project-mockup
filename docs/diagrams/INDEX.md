## คำบรรยายที่ต้องใส่ใต้รูป (thesis-writer)
- Use Case (3.1–3.5): ป้าย include/extend หมายถึง «include»/«extend» (Mermaid ไม่แสดง «») · เส้น association มีหัวลูกศร เป็นข้อจำกัดของเครื่องมือ (UML ปกติเป็นเส้นไม่มีหัว) · ทุกบทบาทเข้าสู่ระบบ ดู "งานของฉัน"/dashboard และอ่านข้อมูลได้ตามสิทธิ์ ไม่ได้วาดเพื่อลดความแน่น (ยกเว้น 3.5 ที่วาด "ผู้ใช้ทุกบทบาท" ไว้) · use case "…ด้วย AI" เป็น extend ของงานหลัก ผู้ใช้ที่ทำได้ตามตาราง 3.2 · 3.1 กับ 3.2 คือระบบเดียวกัน แยกรูปเพื่อให้อ่านได้ · "ส่งรอบกลับแก้ไข" (3.3) ต้องระบุหมายเหตุทุกครั้ง
- Use Case 3.5: "ผู้มีสิทธิ์จัดการผู้ใช้" เป็น actor นามธรรม = บทบาทที่มีสิทธิ์ `user.manage` (ผู้ดูแลมหาวิทยาลัยในมหาวิทยาลัยตน / ผู้ดูแลระบบได้ทุกมหาวิทยาลัย) และสืบทอดจาก "ผู้ใช้ทุกบทบาท" · "จัดการผู้ใช้" ในรูป 3.4 คือกลุ่ม use case เดียวกับฝั่งขวาของรูปนี้ · รีเซ็ตเดโม่ทำได้เฉพาะผู้ดูแลระบบ (`init.ts:124`) · ตั้งค่าการแสดงผลและภาษาทำได้ทั้งก่อนเข้าสู่ระบบ (หน้า login/landing) และหลังเข้า · ผู้ดูแลส่งลิงก์เชิญเอง (คัดลอก) เพราะระบบยังไม่มีอีเมลจริง — ข้อจำกัดเดโม่ · ฟอร์มขอเข้าใช้งานไม่มีช่องบทบาท ผู้อนุมัติเป็นผู้กำหนด
- Activity 3.6: การส่งกลับทุกระดับ (ประธาน/QA/คณบดี) ไปที่ "แก้ตามข้อเสนอแนะ" แล้วส่งข้อใหม่ · "รอข้อถัดไป" = ประธานตรวจข้ออื่นต่อจนครบ 53 ข้อ · "ล็อกข้อ" = ข้อที่ส่งตรวจ/อนุมัติแล้วแก้ narrative คะแนนตนเอง และผูก/เลิกผูกหลักฐานไม่ได้ทั้งที่ UI และ API จนกว่าจะถูกส่งกลับ (`workflow.ts:78-99`) · การส่งกลับระดับรอบต้องมีหมายเหตุ และระบบแจ้งเตือนบทบาทถัดไปอัตโนมัติ · ก่อนเปลี่ยนสถานะรอบ UI แสดงคำเตือน preflight ไม่ได้วาดเป็น action แยก
- Activity 3.7: การส่งผล = `transitionCycle(..., 'assessed')` ซึ่งผ่านได้เมื่อกรรมการทุกคนให้คะแนนครบ 8 เกณฑ์และมี verdict · "รอกรรมการคนอื่น" แล้วกดส่งผลใหม่ · ผลดำเนินการตามแผนกลายเป็นหลักฐานขั้น A ในรอบถัดไปอัตโนมัติ
- Sequence 3.8: "linkEvidence*" ทำเมื่อระบุข้อและรอบ · ถ้าระบุข้อ ระบบตรวจว่ารอบเขียนได้และข้อยังไม่ถูกล็อก **ก่อน**สร้างหลักฐาน (ไม่เกิดหลักฐานกำพร้า, `evidence.store.ts:158-163`) · scanPii ตรวจชื่อ คำอธิบาย ข้อความในไฟล์ และชื่อไฟล์ โดย normalize ก่อน · เมื่อพบไฟล์ซ้ำ (break) ผู้ใช้ยืนยันแล้วเรียก createEvidence ใหม่ด้วย allowDuplicate = true
- Sequence 3.9: "ตัวกรอง*" = AI-2 ตัดประโยคเชิงให้คะแนน/ตัดสิน; AI-4 ตรวจ [E-…] และตัวเลขครบ และติดธงประโยคตัดสินที่เพิ่มมา · AI-1/3/7/9 ใช้โครงเดียวกัน · AI เปลี่ยนสถานะ/ให้คะแนนไม่ได้
- Sequence 3.10: ลำดับการตรวจใน route คือ key → origin/header → rate limit → ขนาด body/JSON/inputGuards → redact ซ้ำ + prompt v2 → งบรายวัน → เรียก Anthropic (timeout 60 วินาที) · ทุกกรณีที่ไม่ได้ 200 ฝั่ง client fallback offline เสมอ
- Sequence 3.11: ก. ผู้ใช้กดออก · ข. AuthContext ตรวจ sessionTimeLeft ทุก 30 วินาที · ค. storage event เมื่อแท็บอื่นออกหรือล็อกอินเป็นคนอื่น · session-lost = หน้าอ่านอย่างเดียวพร้อมปุ่มคัดลอกข้อความ · saveSection ตรวจ conflict เมื่อ `updatedAt` ใหม่กว่า baseUpdatedAt
- Sequence 3.12: "ข้อมูลไม่ผ่าน" = โดเมนอีเมลไม่ใช่ของมหาวิทยาลัยที่ใช้ระบบ / username หรืออีเมลซ้ำ / รหัสผ่านไม่ถึง 8 ตัว / ไม่ได้ติ๊กรับทราบประกาศความเป็นส่วนตัว (PDPA ม.24(3) — "รับทราบ" ไม่ใช่ "ยินยอม") · submitAccessRequest อ่านเฉพาะ field ใน allowlist (กัน mass assignment) ได้ status pending และ roles ว่าง · N12 ส่งให้ผู้มี user.manage ของมหาวิทยาลัยนั้นที่ active · ระหว่างรอ ผู้ขอเข้าสู่ระบบได้ผล error pending (บอกเฉพาะเมื่อรหัสผ่านถูก — ดูรูป 3.17) · อนุมัติแล้ว N12 ของผู้ดูแลทุกคนเป็น "อ่านแล้ว" (คงไว้เป็นประวัติ) · ปฏิเสธ = ลบแถวผู้ใช้และลบ N12 ที่มีชื่อผู้ขอจากผู้รับทุกคน audit เก็บเฉพาะโดเมนอีเมล + หน่วยงาน · กิ่ง error ใช้ได้ทั้ง approve และ reject (managedTarget ตรวจสิทธิ์/สถานะก่อน) · "notification" = notification.store + notification.internal
- Sequence 3.13: token สุ่ม 256 บิตจาก CSPRNG ระบบเก็บเฉพาะ sha256 (`tokenHash`) คืน token ดิบให้ผู้ดูแลครั้งเดียว · ลิงก์ใช้ fragment `#t=` (ไม่ถูกส่งไป server/ไม่เข้า log/Referer) และหน้า /invite ลบออกจากแถบที่อยู่ทันที (replaceState) · "ใช้ไม่ได้" ทุกกรณี (ไม่มี/หมดอายุ/ใช้แล้ว/ยกเลิก/ผู้เชิญไม่ active หรือไม่มีสิทธิ์) ตอบข้อความเดียวกัน (กัน enumeration) · acceptInvitation ตรวจซ้ำหลังคำนวณ hash (กันกดซ้ำ) แล้วเข้าสู่ระบบให้ทันที · ลิงก์ส่งนอกระบบ (ลูกศร async) และใช้ได้เฉพาะเบราว์เซอร์เดียวกันในเดโม่ (ข้อมูลอยู่ใน localStorage) · อายุ 7 วันเป็นค่าที่เลือกเอง ไม่ใช่ข้อกำหนด NIST
- Sequence 3.14: ตัวนับกระดิ่งคำนวณใหม่เมื่อเปลี่ยนหน้า, เมื่อหน้าใดยิง `aunqa:todos-changed` และเมื่อแท็บอื่นเขียน `aunqa_notifications` (storage event) · listNotifications/unreadCount สร้างแจ้งเตือนใกล้ deadline ก่อน (sync) · ระบบเก็บปลายทางแบบความหมาย (`target`) แล้วแปลงเป็น path ภายใน `/app` ที่ฝั่งแสดงผล — ไม่มี URL จากข้อมูล (กัน open redirect) · ข้อความไทยแสดงวันที่เป็น พ.ศ. ที่ชั้นแสดงผล ไม่แก้ข้อมูลที่เก็บ; ภาษาอังกฤษใช้ messageEn · markRead ของบัญชีที่ไม่ active ไม่ทำอะไร · กรณีหน้าเดิมต่างแค่ hash ใช้ pushState + hashchange เพราะ Link ของ Next 14 ไม่ยิง hashchange · หน้าปลายทาง: ข้อ SAR (`#comments` เปิดแท็บความเห็น), รอบ, การประเมิน, แผนปรับปรุง (`#action-…` เลื่อน + ไฮไลต์), ผู้ดูแล (`?tab=requests|users`), หน้าหลัก
