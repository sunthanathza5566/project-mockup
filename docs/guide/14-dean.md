# คู่มือคณบดี (dean)

> บัญชีทดสอบ: `dean1` / `demo1234` — รศ.ดร.สมชาย คณบดีสมมติ (ขอบเขตทั้งคณะ)
> อ่าน [ภาพรวม](00-overview.md) ก่อน ถ้ายังไม่รู้จักคำว่า SAR, ช่องว่าง (gap), hash, revision

คณบดีเป็นผู้อนุมัติสุดท้าย เมื่ออนุมัติแล้ว **รอบจะถูกล็อก** และเป็นฉบับที่ส่งให้กรรมการ

## ทำอะไรได้ / ทำอะไรไม่ได้
| ทำได้ | ทำไม่ได้ |
|---|---|
| "อนุมัติสุดท้ายและล็อก" รอบที่ QA คณะอนุมัติแล้ว | เขียนหรือแก้ SAR หลักฐาน คะแนนตนเอง |
| "ส่งกลับแก้ไข" พร้อมเหตุผล | อนุมัติระดับคณะ (เป็นงานของ QA คณะ) |
| "เปิด revision ใหม่" หลังล็อก (ก่อนเริ่มการประเมิน) | เริ่มการประเมิน มอบหมายกรรมการ ปิดรอบ |
| เพิ่มความเห็นในหน้าข้อ | ใช้ AI |
| ดู audit log ของคณะ ส่งออกเอกสาร | จัดการผู้ใช้ |

## เมนูที่เห็น
หน้าหลัก · รอตรวจ · รอบประเมิน · หลักฐาน · ส่งออกเอกสาร · หลักสูตร · ตัวชี้วัด · แผนปรับปรุง · คลังเกณฑ์ AUN-QA · ผู้ดูแลระบบ (เฉพาะแท็บ Audit log)

## เริ่มจากหน้าหลัก
เมื่อ QA คณะอนุมัติ คุณได้แจ้งเตือน "QA คณะอนุมัติแล้ว — รอคณบดี" (กดแล้วไปหน้ารอบ) และหน้าหลักมีงาน **"พิจารณาอนุมัติสุดท้ายรอบ 2569"** กดปุ่ม "ทำงานถัดไป" หรือ "ไปทำ" หน้าตาโดยรวมดู [ภาพรวม หัวข้อ 5](00-overview.md#5-หน้าตาและการใช้งานพื้นฐาน)

## 1. อนุมัติสุดท้ายและล็อก
1. กดงาน **"พิจารณาอนุมัติสุดท้ายรอบ …"** ในหน้าหลัก → แดชบอร์ดรอบ (`/app/cycles/{รอบ}`)
2. อ่านกล่อง "ขั้นตอนถัดไป": คำเตือนก่อนอนุมัติ เช่น "ยังมีช่องว่างวิกฤต 36 รายการ · หลักฐานที่มีข้อมูลส่วนบุคคลยังไม่ได้จัดการ 1 รายการ" กด "ดูข้อที่เกี่ยวข้อง" เพื่อดูว่าเป็นข้อไหน
3. ต้องการอ่านเล่ม กด **"อ่าน SAR ทั้งรอบ (.docx)"**
4. กด **"อนุมัติสุดท้ายและล็อก"** (ปุ่มหลัก) → กล่องยืนยันอธิบายว่า "เมื่ออนุมัติสุดท้าย รอบจะถูกล็อก แก้ไขเนื้อหา/หลักฐานไม่ได้ และบันทึกลายนิ้วมือเอกสาร (hash)" พร้อมรายการข้อควรระวัง
5. ปุ่ม **"กลับไปตรวจก่อน"** ถูกเลือกไว้ (กด Enter ติดมือ = ยกเลิก) ถ้าแน่ใจ กด "ยืนยันอนุมัติสุดท้ายและล็อก (มีข้อควรระวัง n เรื่อง)"
6. แดชบอร์ดขึ้นแถบ "รอบนี้ถูกล็อกเมื่อ … hash … ตรวจแล้ว เนื้อหา SAR ตรงกับที่ล็อก" QA คณะและผู้ดูแลมหาวิทยาลัยได้รับแจ้งเตือนเพื่อเริ่มการประเมิน

## 2. ส่งกลับแก้ไข
ปุ่ม **"ส่งกลับแก้ไข"** (สีแดง อยู่ขวาสุด แยกจากปุ่มอนุมัติ) → เขียนเหตุผลที่หลักสูตรจะเห็น → ยืนยัน รอบเป็นสถานะ "ส่งกลับแก้ไข" ประธานหลักสูตรได้รับแจ้งเตือน และหน้ารอบของประธานจะมีกล่องบนสุดแสดงชื่อคุณ เวลา และเหตุผลนี้ พร้อมขั้นตอนแก้ เมื่อแก้เสร็จจะผ่าน QA คณะมาใหม่

## 3. เปิด revision ใหม่ (หลังล็อกแล้ว)
ใช้เมื่อพบว่าต้องแก้หลังล็อก แต่ **ยังไม่เริ่มการประเมิน**
1. แดชบอร์ดรอบ → **"เปิด revision ใหม่"**
2. เขียนเหตุผล → ยืนยัน รอบปลดล็อกกลับเป็น "กำลังดำเนินการ" และเลข revision เพิ่มขึ้น 1 (ใต้หัวแดชบอร์ดแสดงเป็น "ฉบับที่ n") ประวัติเดิมยังเก็บไว้
3. หลังเริ่มการประเมินแล้ว ปุ่มนี้จะไม่มี

## เคล็ดลับ
- คำเตือนเป็นข้อมูลประกอบการตัดสินใจ ระบบไม่บังคับหยุด ถ้ามีช่องว่างวิกฤตมาก ควรส่งกลับพร้อมระบุข้อ
- ตัวเลขในวงแหวน "อนุมัติแล้ว 53/53" บอกว่าทุกข้อผ่านประธานแล้ว แต่ "ช่องว่าง" บอกคุณภาพของหลักฐาน ดูทั้งสองอย่าง
- หลังล็อก ตรวจได้ทุกเมื่อว่าเนื้อหายังตรงกับฉบับที่ล็อก จากแถบ hash บนแดชบอร์ด

## ปัญหาที่พบบ่อย
| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| ไม่มีปุ่มอนุมัติ | รอบยังไม่ผ่าน QA คณะ | ดู "ตอนนี้รอ: ใคร" ในกล่องขั้นตอนถัดไป |
| กดยืนยันส่งกลับไม่ได้ | ยังไม่ได้เขียนเหตุผล | เขียนเหตุผลก่อน |
| ไม่มีปุ่ม "เปิด revision ใหม่" | รอบยังไม่ล็อก หรือเริ่มการประเมินแล้ว | เปิดได้เฉพาะช่วงหลังล็อกและก่อนเริ่มการประเมิน |
| กด Enter แล้วไม่เกิดอะไร | ปุ่ม "กลับไปตรวจก่อน" ถูกเลือกไว้เพื่อกันกดพลาด | ใช้เมาส์กดปุ่มยืนยันเมื่อแน่ใจ |
