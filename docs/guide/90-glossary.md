# อภิธานศัพท์ (ไทย–อังกฤษ)

เรียงตามหมวด ศัพท์ที่มีปุ่ม (?) ในระบบ กดดูคำอธิบายสั้นบนหน้าจอได้เช่นกัน

## ศัพท์ AUN-QA และงานประกันคุณภาพ
| คำ | อังกฤษ | ความหมาย |
|---|---|---|
| AUN-QA | ASEAN University Network – Quality Assurance | เกณฑ์ประกันคุณภาพของเครือข่ายมหาวิทยาลัยอาเซียน ระบบนี้ใช้ระดับหลักสูตร ฉบับ 4.0 (8 เกณฑ์ 53 ข้อ) |
| เกณฑ์ | Criterion | หมวดใหญ่ 8 หมวด เช่น เกณฑ์ 5 อาจารย์ |
| ข้อ / ข้อกำหนด | Requirement | ข้อย่อยในเกณฑ์ เขียนเป็นเลข เช่น 3.6 รวม 53 ข้อ |
| SAR | Self-Assessment Report | รายงานการประเมินตนเองของหลักสูตร เขียนตามเกณฑ์ครบ 53 ข้อ ส่งให้กรรมการอ่านก่อนประเมิน |
| คะแนนประเมินตนเอง | Self-rating | คะแนน 1–7 ที่หลักสูตรให้ตัวเองรายข้อ ใช้ทำ Appendix A แยกจากคะแนนกรรมการ |
| คะแนนกรรมการ | Committee rating | คะแนน 1–7 ที่กรรมการให้ **รายเกณฑ์** (8 ค่า) |
| verdict | Overall verdict | ผลสรุปการประเมินภาพรวมของกรรมการ (1–7 พร้อมเหตุผล) กรรมการเลือกเอง ไม่ใช่ค่าเฉลี่ย |
| สเกล 1–7 | Rating scale | 1 ไม่เพียงพออย่างยิ่ง · 2 ไม่เพียงพอ ต้องปรับปรุง · 3 ยังไม่เพียงพอแต่ปรับเล็กน้อยก็พอ · **4 เพียงพอตามที่คาดหวัง (ผ่าน)** · 5 ดีกว่าเพียงพอ · 6 เป็นแบบอย่างที่ดี · 7 ยอดเยี่ยมระดับโลก |
| PDCA | Plan–Do–Check–Act | วงจรพัฒนางาน: วางแผน · ลงมือทำ · ตรวจสอบผล · ปรับปรุง หลักฐานที่ดีควรครบทั้งสี่ขั้น |
| ELO / PLO | Expected / Programme Learning Outcomes | ผลการเรียนรู้ที่คาดหวังระดับหลักสูตร สิ่งที่บัณฑิตทุกคนต้องทำได้เมื่อจบ |
| CLO | Course Learning Outcomes | ผลการเรียนรู้ระดับรายวิชา ต้องผูกกับ PLO |
| I / R / M | Introduce / Reinforce / Master | ระดับที่รายวิชาส่งเสริม PLO: แนะนำ · ฝึกซ้ำ · เชี่ยวชาญ |
| Bloom's Taxonomy | Bloom's Taxonomy | ลำดับการเรียนรู้ 6 ขั้น: จำ เข้าใจ ประยุกต์ วิเคราะห์ ประเมินค่า สร้างสรรค์ ใช้ตรวจคำกริยาใน PLO/CLO |
| OBE | Outcome-Based Education | การศึกษาที่มุ่งผลลัพธ์การเรียนรู้ |
| Constructive alignment | Constructive alignment | ความสอดคล้องระหว่างผลลัพธ์การเรียนรู้ วิธีสอน และวิธีวัดผล |
| วิชาบังคับก่อน | Prerequisite | วิชาที่ต้องเรียนก่อนวิชาอื่น ระบบตรวจไม่ให้วนกัน |
| benchmark / การเทียบเคียง | Benchmarking | ข้อมูลของสถาบันหรือหลักสูตรอื่นที่ใช้เปรียบเทียบผลของเรา |
| ตัวชี้วัด | Metric | ตัวเลขที่ติดตามรายปีหรือรายรุ่น เช่น อัตราการจบ ผลงานวิจัย |
| รุ่น | Cohort | กลุ่มนักศึกษาที่เข้าเรียนปีเดียวกัน ใช้คำนวณอัตราจบและพ้นสภาพ |
| Tracer study | Tracer study | การติดตามบัณฑิตหลังจบ เช่น การได้งานทำ |
| Desktop assessment | Desktop assessment | กรรมการอ่าน SAR และเอกสารก่อนลงพื้นที่ |
| Site visit | Site visit | กรรมการลงพื้นที่ สัมภาษณ์ เยี่ยมชม (ปกติประมาณ 3 วัน) |
| AFI | Areas for Improvement | ข้อเสนอแนะเพื่อการปรับปรุงจากกรรมการ ใช้สร้างแผนปรับปรุง |
| จุดแข็ง | Strengths | สิ่งที่หลักสูตรทำได้ดีตามความเห็นกรรมการ |
| Appendix A | Self-rating checklist | ตารางคะแนนประเมินตนเองรายข้อ ส่งแนบกับ SAR |
| Appendix B | Assessment planning / findings | แบบบันทึกของกรรมการรายข้อ: จุดแข็ง · AFI · คำถามสัมภาษณ์ · แหล่งหลักฐานที่ต้องตรวจ |
| Appendix D | Assessment report | รายงานผลการประเมิน: คะแนนรายเกณฑ์ จุดแข็ง และ AFI |
| แผนปรับปรุง | Action plan / Improvement action | รายการสิ่งที่จะทำเพื่อปรับปรุงตาม AFI มีผู้รับผิดชอบ กำหนดเสร็จ และ KPI |
| CHE QA Online | CHE QA Online | ระบบฐานข้อมูลประกันคุณภาพของ สป.อว. (ระบบนี้ไม่ได้แทน) |

## ศัพท์ของระบบ AUN-QA Copilot
| คำ | อังกฤษ | ความหมาย |
|---|---|---|
| รอบประเมิน | Assessment cycle | การประเมิน 1 ครั้งของ 1 หลักสูตรใน 1 ปีการศึกษา มี 53 ข้อ |
| สถานะรอบ | Cycle status | ร่าง · กำลังดำเนินการ · รอ QA คณะตรวจ · ส่งกลับแก้ไข · QA คณะอนุมัติ · อนุมัติสุดท้าย (ล็อก) · อยู่ระหว่างประเมิน · ประเมินแล้ว · ปิดรอบ |
| สถานะข้อ | Section status | ยังไม่เริ่ม · กำลังเขียน · รอตรวจ · ส่งกลับแก้ไข · อนุมัติแล้ว |
| เจ้าของข้อ | Section owner | ผู้ได้รับมอบหมายให้เขียนข้อนั้น |
| หลักฐาน | Evidence | เอกสาร ไฟล์ ลิงก์ หรือข้อความที่ยืนยันสิ่งที่เขียนใน SAR ชิ้นเดียวผูกได้หลายข้อ |
| รหัสหลักฐาน | Evidence code | รูปแบบ `E-ข้อ-ลำดับ` เช่น `E-1.1-01` ใช้อ้างใน SAR ด้วยวงเล็บเหลี่ยม `[E-1.1-01]` · `E-0.0-nn` คือหลักฐานที่ไม่ได้ผูกข้อตอนสร้าง |
| ผูกหลักฐาน | Link evidence | เชื่อมหลักฐานกับข้อในรอบหนึ่ง โดยไม่คัดลอกไฟล์ |
| ยืนยันหลักฐาน | Verify evidence | ประธานหรือ QA คณะรับรองว่าตรวจหลักฐานแล้ว |
| ช่องว่าง | Gap | สิ่งที่ยังขาดในข้อใดข้อหนึ่ง ตรวจด้วยกฎ R1–R11 มีระดับ วิกฤต · สูง · กลาง · ต่ำ |
| กฎ R1–R11 | Gap rules | R1 ยังไม่มีหลักฐาน · R2 ขาดขั้น Check/Act · R3 ข้อมูลแนวโน้มไม่ครบ 3 ปี · R4 เนื้อหาสั้นกว่า 100 คำหรือว่าง · R5 หลักฐานเก่ากว่า 3 ปี · R6 ข้อมูลส่วนบุคคลค้าง · R7 ข้อมูลหลักสูตรไม่สอดคล้อง · R8 ยังไม่มีการเทียบเคียง · R9 ประโยคไม่อ้างหลักฐาน · R10 คะแนนตนเอง ≥4 แต่หลักฐานไม่ครบ · R11 คำแปลยังไม่ได้ยืนยัน |
| Heatmap | Heatmap | ตาราง 53 ช่องบนแดชบอร์ดรอบ สี + ไอคอน + คำ บอกความพร้อมของแต่ละข้อ |
| ความพร้อมด้านหลักฐาน | Evidence readiness | คะแนนเฉลี่ย 53 ข้อ ตามสถานะข้อ (อนุมัติ 100 · รอตรวจ 90 · กำลังเขียน 50 · ส่งกลับ 40 · ยังไม่เริ่ม 0) หักตามช่องว่าง |
| สิ่งที่ต้องทำตอนนี้ | To-do | รายการงานในหน้าหลัก เรียงตามความเร่งด่วน แต่ละแถวมีปุ่ม "ไปทำ" หายเองเมื่องานเสร็จจริง |
| ทำงานถัดไป | Next task | ปุ่มในการ์ดทักทายของหน้าหลัก พาไปงานแรกที่ควรทำ |
| หลักฐานล็อก | Evidence lock (per requirement) | ข้อที่ส่งตรวจหรืออนุมัติแล้ว ผูก/เลิกผูก/อัปโหลดหลักฐานใหม่ให้ข้อนั้นไม่ได้ จนกว่าจะถูกส่งกลับแก้ไข |
| ส่งตรวจ | Submit for review | ผู้เขียนส่งข้อให้ประธานตรวจ หลังส่งแก้ไม่ได้จนกว่าจะถูกส่งกลับ |
| ส่งกลับแก้ไข | Return for revision | ผู้ตรวจส่งข้อหรือรอบกลับพร้อมเหตุผล (รอบที่ถูกส่งกลับแสดงผู้ส่ง เวลา และเหตุผลบนหน้ารอบ) |
| แยกหน้าที่ผู้เขียนกับผู้อนุมัติ | Segregation of duties | ผู้เขียนข้อล่าสุดอนุมัติข้อนั้นเองไม่ได้ |
| ล็อก | Lock | หลังคณบดีอนุมัติสุดท้าย รอบแก้ไขไม่ได้ |
| hash (ลายนิ้วมือเอกสาร) | Hash / snapshot hash | รหัสที่คำนวณจากเนื้อหา ถ้าเนื้อหาเปลี่ยนแม้ตัวอักษรเดียว รหัสจะเปลี่ยน ใช้พิสูจน์ว่าเอกสารตรงกับที่ล็อก และใช้ตรวจไฟล์ซ้ำ |
| ฉบับที่ / revision | Revision | ครั้งที่ของรอบ (หน้ารอบแสดงเป็น "ฉบับที่ n") เมื่อคณบดีเปิดแก้หลังล็อก เลขเพิ่มขึ้นและเก็บฉบับเดิมไว้ |
| เวอร์ชัน | Version | ฉบับที่บันทึกของเนื้อหาแต่ละข้อ ดูและกู้คืนได้ที่แท็บประวัติ |
| บันทึกอัตโนมัติ | Autosave | ระบบบันทึกเนื้อหาเองระหว่างพิมพ์และเมื่อออกจากหน้า |
| audit log | Audit log | บันทึกทุกการกระทำสำคัญ (ใคร ทำอะไร เมื่อไหร่) เพิ่มได้อย่างเดียว ไม่มีการแก้หรือลบ |
| แจ้งเตือน | Notification | ข้อความในระบบ (ปุ่ม "แจ้งเตือน" รูปกระดิ่ง) เมื่อมีงานถึงคิว ใกล้กำหนดส่ง หรือรอบเปลี่ยนสถานะ กดรายการแล้วไปหน้าของงานนั้น |
| บทบาท / ขอบเขต | Role / Scope | สิทธิ์ของผู้ใช้ และขอบเขตที่สิทธิ์นั้นใช้ได้ (มหาวิทยาลัย คณะ หลักสูตร หรือรอบ) ระบบบังคับให้ขอบเขตตรงกับบทบาท เช่น อาจารย์ = หลักสูตร กรรมการ = รอบ |
| คำขอเข้าใช้งาน | Access request | ผู้ใช้ใหม่กรอกฟอร์มขอบัญชีด้วยอีเมลมหาวิทยาลัย รอผู้ดูแลอนุมัติและกำหนดบทบาท |
| คำเชิญ / ลิงก์เชิญ / รหัสเชิญ | Invitation / invite link / invite code | ผู้ดูแลสร้างบัญชีไว้ล่วงหน้าแล้วส่งลิงก์ให้ผู้ใช้ตั้งรหัสผ่านเอง ใช้ได้ครั้งเดียว หมดอายุ 7 วัน |
| สถานะบัญชี | Account status | ใช้งานอยู่ · รอตั้งรหัสผ่าน (ถูกเชิญ) · รออนุมัติ (ส่งคำขอ) · ระงับ |
| ระงับบัญชี | Suspend | หยุดสิทธิ์เข้าสู่ระบบโดยไม่ลบข้อมูล เปิดใช้อีกครั้งได้ ใช้แทนการลบบัญชี |
| การแสดงผล | Display settings | ขนาดตัวอักษร (ปกติ/ใหญ่/ใหญ่มาก) ธีม (สว่าง/มืด/ตามเครื่อง) และเอฟเฟกต์ฉลอง อยู่ในเมนูผู้ใช้ |
| ธีมตามเครื่อง | System theme | ใช้โหมดสว่างหรือมืดตามการตั้งค่าของคอมพิวเตอร์/มือถือ |
| อ่านอย่างเดียว | Read-only | ดูได้แต่แก้ไม่ได้ เช่น กรรมการต่อ SAR |
| มหาวิทยาลัยแยกข้อมูล | Multi-tenant | ผู้ใช้เห็นเฉพาะข้อมูลมหาวิทยาลัยตน ยกเว้นผู้ดูแลระบบสูงสุด |

## ศัพท์ AI และข้อมูลส่วนบุคคล
| คำ | อังกฤษ | ความหมาย |
|---|---|---|
| PII / ข้อมูลส่วนบุคคล | Personally Identifiable Information | ข้อมูลที่ระบุตัวบุคคลได้ เช่น เลขบัตรประชาชน ชื่อ-สกุล อีเมล เบอร์โทร รหัสนักศึกษา |
| PDPA | Personal Data Protection Act | พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 |
| ปกปิดข้อมูลส่วนบุคคล | Redaction | ก่อนส่งข้อความให้ AI ระบบแทนข้อมูลส่วนบุคคลด้วยเครื่องหมายแทน |
| โหมดในเครื่อง | Offline (deterministic) mode | AI แบบกฎในเครื่อง ไม่ส่งข้อมูลออก ผลเป็นโครงร่างหรือคำแนะนำพื้นฐาน |
| Claude | Claude (Anthropic) | โมเดลภาษาที่ระบบเรียกใช้เมื่อตั้งค่า API key ผลเป็นประโยคอ่านได้ |
| ข้อเสนอของ AI | AI suggestion | ผลจาก AI ที่ยังไม่เข้าเอกสาร ต้องกด "ยอมรับ" ก่อน |
| ตรวจหลังสร้าง | Post-check | ระบบตรวจผล AI: รหัสหลักฐานต้องมีจริง ตัวเลขต้องมีในข้อมูลต้นทาง และตัดประโยคตัดสิน/ให้คะแนน |
| ต่อท้าย / แทนที่ | Append / Replace | วิธีใส่ร่างของ AI: ต่อท้ายเนื้อหาเดิม หรือแทนที่ทั้งหมด (กู้คืนได้จากประวัติ) |
| AI แนะนำข้อแล้ว | Tagged | AI อ่านหลักฐานแล้วเสนอข้อที่เกี่ยวข้อง ผู้ใช้ต้องยืนยันก่อนผูกจริง |
| prompt injection | Prompt injection | ข้อความแฝงคำสั่งในเอกสารที่พยายามหลอก AI ระบบป้องกันด้วยการตรวจหลังสร้างและให้คนยืนยัน |
